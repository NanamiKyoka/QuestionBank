# QuestionMind

**AI 原生的题库与组卷系统** · 后端 Go / 前端 Vue 3

从粘贴文本或上传图片智能录题，到多学科题库管理、知识点语义匹配、审核发布，
再到可视化组卷与一键导出 Word / LaTeX。

## 项目规模

| | 数量 |
|---|---|
| 后端 | 216 个 Go 文件 / 51,510 行（其中测试 14,860 行） |
| 前端 | 83 个 Vue/TS 文件 / 20,077 行 |
| 数据库 | 26 张表 + 一张版本化迁移账本 |
| HTTP 端点 | 120 个 |
| AI 工具 | 41 个（37 服务端 + 4 客户端） |
| 测试 | 642 个 Go 用例 + 283 个 vitest 用例，全部通过 |
| 交付产物 | 两个单文件可执行程序，各约 43 MB |

## 技术栈

| 层 | 选型 |
|---|---|
| 后端 | Go 1.27 · Gin · GORM |
| 数据库 | SQLite（默认，纯 Go 驱动免 CGO）· MySQL |
| 鉴权 | JWT（HS256）+ bcrypt · 字段级 AES-256-GCM 加密 |
| 前端 | Vue 3.5 · Vite · TypeScript（strict）· Pinia · Element Plus · Tiptap · KaTeX |
| 文档导出 | 自研 OOXML 生成器 · 自研 LaTeX→OMML 公式转换 |
| 部署 | 单文件二进制（`go:embed` 内嵌前端），**无任何外部依赖** |

## 快速开始

### Windows（推荐用附带的构建脚本）

`make` 在 Windows 上默认不存在，因此仓库根目录提供等价的 PowerShell 脚本：

```powershell
# 构建：前端 + 服务器版 + 桌面版
.\build.ps1 build

# 桌面版：自动挑空闲端口并打开浏览器，数据落在 ~/.questionmind
.\backend\build\qm-desktop.exe

# 服务器版
.\backend\build\qm-server.exe -addr 127.0.0.1:8080
```

`.\build.ps1 help` 可看全部目标：`web / build / desktop / api / test / check / cross / clean / run`。

### Linux / macOS

```bash
cd backend
make build          # 前端 + 服务器版 + 桌面版
./build/qm-desktop  # 桌面版
./build/qm-server -addr 127.0.0.1:8080
```

首次访问会引导进入初始化向导创建管理员账号。

只想要后端产物（不构建前端）时用 `build.ps1 api` 或 `make build-api`；此时服务端只提供 API。

### 常用命令

| 目的 | Windows | Linux / macOS |
|---|---|---|
| 开发模式运行 | `.\build.ps1 run` | `make run` |
| 全量单元测试 | `.\build.ps1 test` | `make test` |
| 提交前检查 | `.\build.ps1 check` | `make check` |
| 交叉编译六份产物 | `.\build.ps1 cross` | `make cross` |
| 只构建前端 | `.\build.ps1 web` | `make web` |

### 配置

优先级：环境变量 > `config.yaml` > 内置默认值。

| 变量 | 默认 | 说明 |
|---|---|---|
| `QM_DATA_DIR` | `~/.questionmind` | 运行期数据目录（数据库、上传、日志、密钥） |
| `QM_HOST` / `QM_PORT` | `127.0.0.1` / `8080` | 监听地址 |
| `QM_MODE` | `debug` | `release` 会关闭调试信息与路由表打印 |
| `QM_DB_DRIVER` | `sqlite` | `sqlite` 或 `mysql` |
| `QM_DB_DSN` | 自动 | MySQL 连接串 |
| `QM_JWT_SECRET` | 自动生成并持久化 | 留空则首次运行生成 `secret.key` |

完整清单见 [`.env.example`](.env.example)（仅供查表，进程不读 `.env` 文件）。

```
│   ├── ai/                # OpenAI 兼容客户端（隔离外部接口）

│   ├── pdfium/            # PDF 渲染成页图（PDFium wasm + wazero，纯 Go，无 cgo）

│   ├── export/            # 导出中间表示（DOCX 与 LaTeX 共用）
│   ├── infra/             # OMML 转换、DOCX/LaTeX 写出、向量、存储

frontend/src/
├── api/                   # 接口层（含响应信封拆包与错误归一）
├── stores/                # 认证、当前学科
├── router/                # 路由与三类守卫（未初始化/未登录/非管理员）

├── components/            # 富文本编辑器、只读渲染、题目编辑对话框

docs/DESIGN.md             # 设计文档（需求、架构、数据模型、API、决策记录）
docs/DEFENSE.md            # 答辩材料（演示脚本、问答、难点）
analysis/                  # 参考项目调研笔记
```

- [x] JWT 鉴权、bcrypt 密码、首次运行初始化向导（未初始化时接口统一 503）
- [x] 学科、学科成员与四级角色、知识点树（物化路径 + 防成环移动）
- [x] 标签与标签分类
- [x] 题目 CRUD、五种题型的领域校验、多条件筛选、批量操作、软删除与回收站
- [x] 母子题（材料题）结构：母题/小问的建题、改挂与结构展示
- [x] 审核工作流（草稿 → 待审 → 发布 → 归档，按学科阈值）与审核日志
- [x] 用户管理与 RBAC，含「最后一个管理员」保护
- [x] 操作审计日志（异步有损队列，动作名由路由模式推导）与操作日志页

### 组卷与导出

- [x] 组卷工作台：目录树、两层 AST 排版节点、服务端派生解析条目
- [x] **题目内容冻结**：入卷时快照，题库之后怎么改都不动已排好的卷子
- [x] 乐观锁整树保存、题目时效性检测与显式同步、不可变版本快照、版本预览、操作时间线
- [x] 每题题号与分值：支持按标题分组的 1.1 式编号，横线答题区
- [x] 试题篮（跨页面暂存）、从题库把选中题目并入现有或新建试卷
- [x] 导出 Word（自研 OOXML 生成器）与 LaTeX（打包为 zip）
- [x] 自研 LaTeX→OMML 转换：导出的公式在 Word 里可编辑
- [x] 自研 .docx **读取**（archive/zip + OOXML，含 OMML 公式、表格与 Word 自动编号还原），无 cgo、无 pandoc

### AI 原生

- [x] AI 供应商与模型配置：AES-256-GCM 加密密钥、掩码回显、三态更新、连通性测试
- [x] 协议清单由服务端下发并在保存时强校验，不存在"能选不能用"的供应商
- [x] 模型能力**多选**：同一个多模态模型可同时充当文本与视觉模型，不必录两遍
- [x] OpenAI 兼容客户端：流式、工具调用、退避重试、超时、多模态
- [x] 智能录题：**两条解析路径**——模型抽取，或免 AI 的确定性标签解析器（含文末答案区）
- [x] 「仅录题」：只抽题目不求解（省掉最贵的那部分输出），答案标为「待补充」，识别后**可直接入库**
- [x] **抽取结果落库**：草稿存在导入任务里，刷新页面或换个浏览器都能接着入库
- [x] 智能录题输入：粘贴文本、图片、`.md` / `.txt` / `.docx` / `.pdf` / `.zip`（含 zip-slip 与压缩炸弹防护）
- [x] **答案页随卷上传**：卷子不带答案时，让模型把二十道解答题自己算一遍要三万输出 token；
  附上答案页后模型只需转写，快一个数量级，对不上的题留空并标注
- [x] **PDF 自动转图后按视觉识别**：PDF 文本层对数学公式是结构性失效的（公式由定位字形排版，
  取字时上下标与分式的分子分母会被拆到相邻行）。改为先渲染成页图交给视觉模型：
  实测同一份全国卷，题干里的字母从 9 个变成 696 个。渲染用 PDFium 的 WebAssembly 构建
  + wazero（纯 Go 运行时），**不需要 cgo**，仍可交叉编译六个目标、单文件部署
- [x] 自研 PDF 文本层读取（xref 表与流、对象流、ToUnicode CMap），零 cgo；
  保留为渲染不可用时的回退路径
- [x] **长文档分块并发抽取**：按题数切块、4 路并发、块间临时编号重挂；实测整卷导入从"超时失败"降到约 4.6 分钟
- [x] **页图按页分批 + 截断自适应细分**：模型单次输出有上限（常见 32K），超出部分会被截断且 JSON 残缺，
  整份卷子一道题都读不出来。页图路径按页分批；某批超限时先拆页，仍超则**按行间空白把页面横向切开**重试。
  实测 2026 全国 1 卷完整抽取从"11 道（2/3 页失败）"变为"36 道、零截断"
- [x] 逐题可编辑审核、按来源文件分组、部分成功入库、导入历史与重试
- [x] **题库内 AI 解题**：单题或多选批量补写答案与解析；已有答案默认不覆盖（要覆盖先问一次）
- [x] 批量排队导入：一次提交整个文件夹，后台 worker 依次处理，可放弃、可重试
- [x] 整卷导入：解析时保留版面大纲（标题、题间说明、题目顺序），可一键还原成可编辑试卷
- [x] AI 助手：Agent 工具循环（轮次 / 工具数 / 墙钟三重预算）、SSE 流式、41 个工具
- [x] **批量整理题库**：单条改、批量改、语义归类、试卷与知识点维护，全部走 service 层，
  与用户在界面上操作共用同一套鉴权与状态机
- [x] **`dry_run` 预演闸门**：批量工具省略该参数即等同预演；预演读的是真实权限与状态，
  因此不会与 service 层的守卫漂移
- [x] 客户端工具通道：AI 改的是用户眼前那份未保存的卷子，且**改动先预览、由用户应用或放弃**
- [x] 提示词可配置：全局模板 + 学科覆盖，界面显示当前实际生效的来源
- [x] 知识点向量索引与语义检索（进程内余弦，无外部向量库）
- [x] 知识点变更自动维护索引；混用模型时提示重建

## 未实现（诚实记录）

| 项 | 原因 |
|---|---|
| 系统托盘 | 纯 Go 实现需约 200 行 win32 syscall，本环境无法验证图标与点击是否真的生效；不在进程启动路径上放无法验证的代码 |
| Docker / 镜像 | 单二进制已覆盖部署需求；CI 已覆盖 `make check` 的同等检查项（另加 `-race`、`vue-tsc`、`vitest` 与 `vite build`） |
| PDF 导出 | LaTeX 产物可交本机 TeX 发行版编译；自研 PDF 生成器成本远高于收益 |
| PDF 导入的**矢量图形** | 页面按位图渲染，模型看到的是像素：几何图里的线条会以图像形式出现在题干里，但不会变成可编辑的图形对象。几何图仍需人工补图——这一点不是渲染精度问题，而是"截图"与"矢量对象"之间的鸿沟 |
